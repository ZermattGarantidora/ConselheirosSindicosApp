# Resultado local — próxima pergunta antes de encerrar o cadastro

**Data:** 03/11/2026  
**Escopo:** RQ-2402 e RQ-2605, AC-2403a; validação sintética local.

Após confirmar o nome do condomínio, o cliente aguardava apartamentos, mas aceitava uma fala
que anunciava o contexto salvo e convidava ao envio de documentos. O validador conferia os
quatro campos estruturados, sem conferir a próxima pergunta na fala.

`setup-turn.ts` agora fornece as próximas etapas possíveis e valida a fala contra a transição
confirmada, usando `setup-turn-flow.ts`. Uma saída com dados válidos e pergunta ausente ou
conclusão explícita antecipada admite uma reparação pelo mesmo gateway/tarefa, mantendo intenção,
campo e valor. Uma nova falha resulta em erro recuperável; a fala rejeitada não é publicada ou
gravada no journal. Falas válidas usam uma geração; JSON inválido ou com propriedades extras
continua recusado sem reparação. O system prompt v27 e os tetos por geração foram preservados.
Uma reparação pode acrescentar uma geração, sem classificador pago ou escalada intencional.

## Evidências

- Regressões antes da implementação: 13 falhas entre 35 testes, incluindo encerramento após
  o nome, ausência da pergunta, preservação dos dados na reparação e metadados de transição.
- Regressões HTTP em `api-setup-message.test.ts`: somente a fala reparada válida entra no
  histórico; segunda fala incompatível ou dado alterado retorna 502 sem entrada de sucesso.
- A fixture Gemini passou a perguntar pelo campo correto em cada etapa; asserções de schema,
  recusa de propriedades extras, campos ausentes e enums inválidos foram mantidas.
- Suite completa: 1.767 testes em 172 arquivos aprovados. Cobertura: statements 91,46%,
  branches 87,71%, functions 96,19% e lines 93,13%. `pnpm run check` completo aprovado:
  formatação, lint, tipos, visão de 61 specs e scanner de segredos sem padrão conhecido.
- `pnpm run evals`: 20/20; `pnpm run evals:documentary`: 50/50 determinísticos; build API aprovado.
- Três gerações reais sintéticas pelo Codex local, Luna high: nome → pergunta de unidades;
  unidades do primeiro de dois → nome do segundo; últimas unidades → conclusão e documentos.
  Todas passaram em uma geração, sem API paga e sem dados do usuário. Isso não constitui
  uma nova bateria comparativa nem validação estatística.

Artefatos locais: `.local/setup-flow-fix/` contém baseline, diferenças, logs, resultado do
smoke e manifesto SHA-256 dos cinco arquivos de fonte/testes.

## Limites

O guard de saída cobre perguntas explícitas de configuração e sinais de conclusão prematura;
não é um classificador semântico geral. Uma formulação não reconhecida pode exigir a reparação
ou uma nova resposta da pessoa. Não altera cadastro a partir de palavras-chave da entrada,
autorização, documentos, persistência, retenção ou criação de condomínios.

A API foi reiniciada após confirmação explícita do usuário sobre a perda do estado em RAM,
conforme briefing §8. O novo processo usa a correção; `/v1/runtime` respondeu `ok`, provedor
`codex`, histórico `volatile`, e o frontend respondeu HTTP 200. Vite foi preservado; não foram
removidos arquivos ou perfis do navegador. A aba antiga precisa de recarga para obter uma nova
sessão de cadastro, pois o identificador anterior também era mantido em RAM. Revisão
independente e CI do branch completo seguem necessários antes de merge.
